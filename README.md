# HELLS UP

Премиальное **Telegram Mini App** в чёрно-золотом стиле: кейсы, инвентарь, улучшение предметов (Upgrade), общая рулетка, Blackjack, чат поддержки и админ-панель.

> ⚠️ **Только демо.** Баланс — виртуальные монеты, предметы — вымышленные. Вывода, обмена и денежных выплат нет, и в схеме БД для них нет таблиц. Все результаты игр, изменения баланса и операции считаются и проверяются на сервере.

**Стек:** Next.js 15 (App Router) · TypeScript · Tailwind CSS · Framer Motion · Radix UI · Supabase (PostgreSQL + Realtime) · Telegram Mini Apps SDK · Zod · TanStack Query · Zustand · Vitest · Playwright. Деплой — Vercel.

## Безопасность (кратко)

- **Telegram initData** проверяется на сервере (HMAC-SHA256 по токену бота, `auth_date`, защита от подделки). Сессия — подписанный JWT в `httpOnly` cookie, пользователь перепроверяется в БД на каждом запросе.
- **Клиент не присылает результатов**: только действия («открыть кейс X»). `roll` генерирует сервер (`HMAC-SHA256`, криптостойкий `crypto`).
- **Деньги — только через PostgreSQL-функции** в одной транзакции с блокировкой строки пользователя; баланс целочисленный, `CHECK (balance >= 0)`, каждое изменение пишется в `transactions`.
- **Idempotency key** на каждую игровую операцию; CSRF-заголовок на изменяющих запросах; Zod на всех входах; rate limiting.
- **RLS**: клиентские роли не имеют доступа к таблицам, кроме публичных данных рулетки/ленты и собственных обращений поддержки. RPC-функции доступны только `service_role`.
- **Админы** задаются только переменной `ADMIN_TELEGRAM_IDS` (роль не хранится в БД и не может быть изменена пользователем). Все действия админов — в `audit_log`.
- **Demo-вход** без Telegram работает только при `next dev` и `DEMO_MODE=true`; в production игнорируется.
- Секреты — только в переменных окружения Vercel, ни одного в репозитории (`npm run check:secrets`).

## Подключение (всё делается с телефона)

Понадобятся: аккаунт **GitHub** (уже есть), **Supabase**, **Vercel**, **Telegram**.

### 1. Supabase — база данных

1. Зайдите на [supabase.com](https://supabase.com) → **New project** (регион поближе, запомните пароль БД).
2. Откройте **SQL Editor** → **New query**.
3. Откройте файл [`supabase/setup.sql`](supabase/setup.sql) в этом репозитории (кнопка **Raw** → выделить всё → копировать), вставьте в редактор и нажмите **Run**. Скрипт создаёт таблицы, функции, RLS и демо-контент (8 кейсов, 34 предмета). Выполнять **один раз**.
4. **Project Settings → API** — скопируйте:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` ключ → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` ключ → `SUPABASE_SERVICE_ROLE_KEY` (**секрет!**)
   - (необязательно) **JWT Settings → JWT Secret** → `SUPABASE_JWT_SECRET` — включает приватный Realtime чата. Без него чат работает через опрос каждые несколько секунд.
5. Realtime: в `setup.sql` таблицы уже добавлены в публикацию `supabase_realtime`.

### 2. Telegram — бот

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username. Сохраните **токен** → `TELEGRAM_BOT_TOKEN` (**секрет!**).
2. Свой Telegram ID можно узнать у бота [@userinfobot](https://t.me/userinfobot) → это значение для `ADMIN_TELEGRAM_IDS` (несколько — через запятую).
3. После деплоя (шаг 3): BotFather → `/mybots` → ваш бот → **Bot Settings → Menu Button → Configure menu button** → вставьте URL приложения с Vercel и название кнопки (например, «Играть»).
   Либо `/newapp` для Mini App со ссылкой вида `t.me/<bot>/<app>`.

### 3. Vercel — деплой

1. [vercel.com](https://vercel.com) → войдите через GitHub → **Add New → Project** → выберите репозиторий `Hells-up`.
2. Framework определится как Next.js. В **Environment Variables** добавьте (см. `.env.example`):

| Переменная | Откуда | Секрет |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → API | нет |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase → API | нет (публичный) |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → API | **да** |
| `SUPABASE_JWT_SECRET` | Supabase → JWT Settings (необязательно) | **да** |
| `TELEGRAM_BOT_TOKEN` | BotFather | **да** |
| `SESSION_SECRET` | любая случайная строка 32+ символов | **да** |
| `ADMIN_TELEGRAM_IDS` | ваш Telegram ID | да |
| `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` | имя бота без @ (необязательно) | нет |

   > Для `SESSION_SECRET` можно взять любой длинный случайный набор символов (например, сгенерированный менеджером паролей на телефоне).
3. **Deploy**. Получите адрес вида `https://hells-up-xxx.vercel.app` и вставьте его в BotFather (шаг 2.3).
4. Откройте бота в Telegram → кнопка меню → приложение запустится. Если чего-то не хватает, приложение само покажет экран «Приложение ещё не подключено» со списком недостающих переменных (статус — `/api/health`). После изменения переменных нажмите **Redeploy**.

### 4. Первый запуск

1. Откройте приложение из Telegram — пользователь создастся автоматически (старт: 5 000 монет).
2. Если ваш ID в `ADMIN_TELEGRAM_IDS`, в **Профиле** появится «Админ-панель» (`/admin`).
3. Настройте стартовый баланс, лимиты и баннер в **Админка → Настройки / Игры**.

## Как это работает

- **Кейсы:** сервер берёт `nonce` активного seed игрока, считает `roll`, функция `open_case` выбирает предмет по весам, списывает цену, выдаёт предмет и пишет снимок шансов — всё в одной транзакции. Цена кейса в seed = ожидаемая стоимость / 0.94 (возврат ≈ 94%).
- **Upgrade:** шанс = `цена_входа / цена_цели × (1 − комиссия)` (комиссия и максимум настраиваются), минимум 1%. Стрелка на шкале останавливается в точке `roll`, вернувшейся с сервера.
- **Рулетка:** на Vercel нет постоянного процесса, поэтому раунд «тикает» лениво: любой запрос состояния продвигает раунд (идемпотентно, под блокировкой БД). Результат раунда — `HMAC(server_seed, id_раунда)`, хэш seed публикуется заранее, сам seed — после раунда.
- **Blackjack:** колода тасуется детерминированно из seed; в браузер отдаются только открытые карты. Каждое действие применяется к конкретной версии партии (защита от двойных нажатий).
- **Rate limiting** — в памяти инстанса (мягкая защита); жёсткая защита от повторов — блокировки и idempotency-ключи в PostgreSQL.

## Что требует ручной настройки

Supabase-проект и выполнение `setup.sql`, бот в BotFather, переменные окружения в Vercel, кнопка меню/Mini App в BotFather. Подключение остальных интеграций (платежи, вывод) **не предусмотрено намеренно**.
